# User Spec: pricing-panel-tweaks

## What we're building
На странице poshivon.ru/panel (раздел «Настройки» ценового калькулятора) меняем
порядок и названия тарифных режимов, добавляем возможность добавлять новые
строки в трёх списках (Изделия, Усложнения, Скидки по партиям) и переименовываем
одну надпись.

## Why
Текущие названия тарифов («Шедевр», «По быстрому») и их порядок не отражают
то, как их хочет видеть админ. Кроме того, в панели сейчас нет способа
добавить новое изделие, усложнение или диапазон скидки — список ограничен тем,
что было изначально задано в коде/сохранено ранее. Админу нужно расширять эти
списки самостоятельно, без правки кода.

## How it should work
1. Админ открывает poshivon.ru/panel → «Настройки».
2. В переключателе режима калькулятора видит режимы в новом порядке: сначала
   «Продвинутый» (бывший «Шедевр»), затем «Быстрый» (бывший «По быстрому»).
   Внутренние значения режимов (`masterpiece`/`quick`), от которых зависит
   расчёт цены и хранение данных, не меняются — меняется только видимый текст.
3. В блоке «Изделия» админ видит кнопку «Добавить» → нажимает → открывается
   форма (Название, Мин. цена / шт — в быстром режиме) → заполняет → новая
   строка попадает в список на экране.
4. Аналогично в блоке «Усложнения»/«Операции» (Название + Надбавка, %) и в
   блоке «Скидки за количество» (диапазон количества + процент скидки) —
   каждая кнопка «Добавить» независима от того, какой режим калькулятора
   сейчас активен (всего 3 кнопки на весь экран, не по одной на каждый режим).
5. Админ нажимает существующую кнопку «Сохранить изменения» — весь набор
   настроек, включая новые строки, сохраняется на сервере.
6. После перезагрузки страницы все добавленные строки остаются на месте.
7. Если админ пытается добавить изделие/усложнение с именем, которое уже есть
   в списке, форма показывает ошибку и не даёт добавить дубликат.
8. Надпись «Скидки по партиям» везде на экране заменяется на «Скидки за
   количество» (в коде название хранится во множественном числе).

## Acceptance Criteria
- [ ] Порядок тарифных режимов на /panel изменён: бывший второй режим теперь
      показывается первым.
- [ ] Названия режимов — «Продвинутый» и «Быстрый»; внутренние значения
      (`masterpiece`/`quick`) в коде, БД и расчётах не изменены.
- [ ] Ровно 3 кнопки «Добавить» на экране: у Изделий, у Усложнений/Операций и
      у Скидок за количество — каждая видна независимо от активного режима
      калькулятора (не дублируется на каждый режим).
- [ ] Добавление строки в любом из 3 блоков + нажатие «Сохранить изменения» →
      строка сохраняется и остаётся после перезагрузки страницы.
- [ ] Добавление изделия через форму быстрого режима не приводит к ошибке
      сохранения (скрытые обязательные поля backend'а получают безопасные
      значения по умолчанию).
- [ ] Попытка добавить изделие/усложнение с именем, которое уже есть в
      списке, блокируется на клиенте с понятной ошибкой (не перезаписывает
      существующую запись молча).
- [ ] Надпись «Скидки по партиям» заменена на «Скидки за количество» везде,
      где отображается (общий компонент для обоих режимов).

## Constraints
- Это **live продакшн-панель** — изменения не должны сломать уже сохранённые
  данные (существующие изделия, усложнения, скидки, значения тарифов).
- Переименование меток тарифов должно менять только отображаемый текст
  (`label`), не трогая внутренний ключ (`value: "masterpiece"/"quick"`), от
  которого зависит расчёт цены и хранение результатов расчётов.
- Настройки (изделия/усложнения/скидки) хранятся **на пользователя** — у
  каждого аккаунта с доступом к панели свой независимый набор данных, это не
  единый общий прайс-лист сайта. Новая строка появляется только в настройках
  того, кто её добавил — это ожидаемое, не побочное поведение.
- Backend требует `base_minutes > 0` и `complexity_coeff > 0` для любого
  изделия независимо от режима калькулятора — форма добавления в быстром
  режиме (которая не показывает эти поля) должна подставлять безопасные
  значения по умолчанию, иначе сохранение всей формы настроек отклоняется.
- Никаких новых бэкенд-эндпоинтов не требуется: сохранение уже идёт одним
  запросом (весь объект настроек), новую строку достаточно добавить в
  локальное состояние формы перед нажатием существующей кнопки «Сохранить».

## Risks
- **Риск:** Переименование меток тарифов может задеть места, где название
  используется как идентификатор. **Mitigation:** проверено в коде — «Шедевр»/
  «По быстрому» встречаются только как текст (`label`), реальный ключ везде —
  `masterpiece`/`quick`; правится только текстовое поле.
- **Риск:** Добавление изделия через форму быстрого режима не пройдёт
  валидацию backend'а (`base_minutes`/`complexity_coeff` обязательны и должны
  быть > 0), и сохранение всей формы настроек (включая другие несвязанные
  правки в той же сессии) молча откажет. **Mitigation:** форма добавления
  всегда передаёт безопасные скрытые значения по умолчанию для этих полей.
- **Риск:** Изделия/усложнения — это map по имени без проверки дублей на
  backend'е; добавление строки с существующим именем тихо перезапишет старую
  запись. **Mitigation:** проверка на дубликат имени добавлена на клиенте перед
  отправкой формы.

## Technical Decisions
- Переименование и смена порядка тарифов делается правкой только поля
  `label` (и порядка элементов массива) в `calculatorModes` — поле `value`
  не трогается.
- «Добавить» не создаёт новый сетевой запрос — новая строка добавляется в
  локальное состояние формы и сохраняется вместе со всеми остальными полями
  через уже существующую кнопку «Сохранить изменения» (единый
  `POST /api/v1/users/settings`). Отдельного автосохранения не вводим — это
  был бы новый паттерн, не используемый больше нигде в панели.
- Форма добавления изделия в быстром режиме подставляет скрытые значения по
  умолчанию для `base_minutes`/`complexity_coeff`, чтобы пройти обязательную
  backend-валидацию, даже когда эти поля не показываются пользователю.
- Добавляем проверку на клиенте: нельзя добавить изделие/усложнение с именем,
  которое уже есть в списке.
- Модель «настройки на пользователя» — существующее и осознанное поведение
  системы, менять её в рамках этой задачи не будем.

## Testing

**Unit tests:** always done, not up for discussion.

**Integration tests:** нет — небольшая фронтенд-правка без новых бэкенд-эндпоинтов
и без изменения схемы данных; риск локализован и покрывается ручной проверкой.

**E2E tests:** нет — задача небольшая (Size S), достаточно ручной проверки на
живой панели.

## How to Verify

### User verifies
- Открыть poshivon.ru/panel → «Настройки» и визуально проверить: порядок
  тарифов поменялся, названия — «Продвинутый»/«Быстрый», надпись «Скидки за
  количество» вместо «Скидки по партиям».
- Добавить одну новую строку в каждом из 3 блоков (Изделия, Усложнения,
  Скидки за количество) через кнопку «Добавить», нажать «Сохранить
  изменения», перезагрузить страницу — убедиться, что все 3 строки остались.
- Попробовать добавить изделие/усложнение с именем, которое уже есть в
  списке — убедиться, что появляется ошибка и дубликат не добавляется.
