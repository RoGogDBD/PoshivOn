# Task 1: Rename and reorder calculator modes, rename discount label (Increment 1)

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

This is Increment 1 from user-spec — the complete, independently-deployable
"rename/reorder/label" slice of the `pricing-panel-tweaks` feature. It is a
pure data edit in `client/src/pages/Panel.jsx`: no state, no handlers, no new
components, no network calls. Three edits, all display-text only:

1. Swap the position of the two entries in the `calculatorModes` array
   (currently `masterpiece` at index 0, `quick` at index 1 → after this task,
   `quick` at index 0, `masterpiece` at index 1) and rename their `label`
   strings. See the note below — user-spec's own text has an internal
   inconsistency about the resulting visual order; this task follows
   tech-spec Decision 1's explicit instruction ("swap the two array entries'
   positions"), which matches user-spec's Acceptance Criteria wording ("бывший
   второй режим теперь показывается первым" — the former second mode, `quick`,
   now shows first).
2. Update the hardcoded fallback string used when no mode matches.
3. Rename the `DiscountsBlock` section title.

**Note on order — flag for Verify-user:** user-spec's narrative step 2 text
("сначала «Продвинутый»... затем «Быстрый»") literally describes the *same*
position as today (masterpiece/Продвинутый already renders first, before any
swap) — i.e. read literally, step 2's words describe a rename-only, no-swap
outcome. But user-spec's own Acceptance Criteria says "бывший второй режим
теперь показывается первым" (the former second — `quick`/Быстрый — now shows
first), which requires an actual swap and produces the *opposite* visual
order from step 2's words (Быстрый first, Продвинутый second). Tech-spec
Decision 1 resolves this by explicitly instructing a positional swap, so this
task implements the swap (Быстрый first, Продвинутый second on screen). Since
this task's `verify` is user-only, call this out explicitly when asking the
user to verify — if the swapped order isn't what they intended, this is the
one behavior in this task worth double-checking against their actual intent
rather than assuming the implementation is correct.

Per tech-spec Decision 1, only the `label` (display text) fields change. The
`value: "masterpiece"` / `value: "quick"` fields — the actual identifiers used
in calculation logic (`isQuickCalculator = calculatorMode === "quick"`),
storage (`pricing_rules.calculator_mode`), and `normalizeCalculatorMode`
(`Panel.jsx:1421`) — must never be touched. This keeps the change
zero-behavioral-risk on a live production panel: nothing about how prices are
calculated or stored changes, only what the admin reads on screen.

Confirmed by grep across the whole file: `"Шедевр"`, `"По быстрому"`, and
`"Скидки по партиям"` each occur exactly once, at the three lines listed
below — there is no other place in the codebase where these display strings
are duplicated or where the rename could be missed.

## What to do

- In the `calculatorModes` array (`Panel.jsx:83-94`): swap the position of the
  two object entries so the array's first element is the one with
  `value: "quick"` and the second is the one with `value: "masterpiece"` —
  this makes the mode switcher show "Быстрый" first, "Продвинутый" second
  (per tech-spec Decision 1 and user-spec's AC "бывший второй режим теперь
  показывается первым"; see the order note above — surface this to the user
  during Verify-user). Rename `label: "Шедевр"` → `label: "Продвинутый"` and
  `label: "По быстрому"` → `label: "Быстрый"`. Do not change either `value`
  field or either `description` field.
- Update the fallback string on `Panel.jsx:798`
  (`calculatorModes.find(...)?.label || "Шедевр"`) from `"Шедевр"` to
  `"Продвинутый"` so the fallback stays consistent with the renamed label (it
  is the string shown if `calculatorMode` somehow matches no entry — should
  mirror whichever label was "Шедевр" before, now "Продвинутый").
- In `DiscountsBlock` (`Panel.jsx:1258-1262`), change the `title` prop passed
  to `SettingsSection` from `"Скидки по партиям"` to `"Скидки за
  количество"`. `DiscountsBlock` is already a single shared component invoked
  from both calculator-mode branches, so this one edit covers both branches
  automatically (matches user-spec AC "надпись... заменена... везде, где
  отображается (общий компонент для обоих режимов)").
- Do not touch `quick_price`, `quick_percent`, `isQuickCalculator`,
  `normalizeCalculatorMode`, `pricing_rules.calculator_mode`, or any other
  occurrence of the substring `quick`/`masterpiece` outside these three
  `label`/title edits — confirmed via grep that all other occurrences are the
  real internal identifier, not display text.
