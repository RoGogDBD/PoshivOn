- `/skill:pre-deploy-qa` — [skills/pre-deploy-qa/SKILL.md](~/.claude/skills/pre-deploy-qa/SKILL.md)

## Description

Final wave, pre-deploy acceptance testing for the whole `pricing-panel-tweaks` feature. This task closes out both increments (Инкремент 1 — rename/reorder/label from Task 1; Инкремент 2 — add/delete rows for Изделия/Усложнения/Скидки за количество from Tasks 2-5) before the feature is considered ready to deploy.

This feature has no agent-executable live-environment check: per tech-spec's Agent Verification Plan, `/panel` requires an authenticated admin session (Яндекс login + granted access) the agent doesn't have, and there is no MCP or curl-checkable API for this UI. All behavioral acceptance criteria in both user-spec and tech-spec are therefore verified by a manual checklist the *user* walks through on the live/dev panel (user-spec "How to Verify → User verifies", extended per-task by the `Verify-user` fields in tech-spec Tasks 1, 3, 4, 5). This task's own job is narrower than a typical pre-deploy-qa task: it (a) runs the one thing that *is* agent-executable — `npx vitest run` — and (b) confirms, together with the user, that the manual checklist was actually walked through and that its outcome matches every AC in user-spec and tech-spec. It does not attempt to execute the manual checklist itself.

Do not mark this feature ready to deploy if any vitest test fails, any AC checkbox is unmet, or the user has not actually walked the manual checklist.

## What to do

- Run `npx vitest run` (from `client/`) and confirm the test file added in Task 2 passes in full — covering name-dedup checks, numeric bound checks for garment/operation/discount fields, `DEFAULT_GARMENT_NAMES`/`DEFAULT_OPERATION_NAMES` exact-match assertions, and `getDefaultDiscountRange`.
- Walk through every Acceptance Criteria checkbox in [user-spec.md](../user-spec.md)'s Acceptance Criteria section, both subsections, and record a pass/fail for each:
  - Инкремент 1 (3 checkboxes): mode order swapped, labels "Продвинутый"/"Быстрый" with `masterpiece`/`quick` values unchanged, "Скидки по партиям" → "Скидки за количество" everywhere.
  - Инкремент 2 (8 checkboxes): 3 "Добавить" buttons always visible with identical form/behavior across both calculator modes; add-form shows all fields with no hidden defaults; add-form rejects out-of-bounds values (garment ≤0 fields, discount range/percent bounds); a saved add survives reload and prices correctly in both modes; discount add-form pre-fills a valid full range (min_qty and max_qty both) continuing the last tier; duplicate-name add is blocked client-side with the "Такое название уже есть" message; "Удалить" is visible/working only on admin-added Изделия/Усложнения rows (absent on the 4/8 defaults) and persists after reload; "Удалить" on Скидки за количество works on any row except the last remaining one (disabled there).
- Walk through every Acceptance Criteria checkbox in [tech-spec.md](../tech-spec.md)'s own Acceptance Criteria section (the 8 technical criteria: `calculatorModes[*].value` unchanged, no new backend endpoints, `DEFAULT_GARMENT_NAMES`/`DEFAULT_OPERATION_NAMES` match `DefaultUserSettings()` exactly, client validation bounds equal-or-stricter than backend, both mode branches render the new components identically, `getDefaultDiscountRange` fills both ends, `npx vitest run` passes, no regressions in existing settings fields).
- Confirm with the user that the manual verification checklist in user-spec "How to Verify → User verifies" — extended by the `Verify-user` fields of Tasks 1, 3, 4, 5 (mode/label check; add+save+reload+price-check for each of the 3 blocks; boundary-rejection checks per block; default-row delete-button absence; middle-tier-delete-then-reload check; last-tier delete-disabled check; duplicate-name rejection check) — has actually been walked through on the live/dev panel, and that its outcome matches the AC above. This is a confirmation, not an agent-executed check: report what the user observed, do not fabricate or assume a pass.
- Produce a QA pass/fail report: vitest result, AC checklist results (both specs), confirmation status of the manual checklist. If anything fails or is unconfirmed, the feature is not ready to deploy — report exactly what is missing/failing so it can be routed back to the relevant task.

## Verification Steps

### Automated
- `cd client && npx vitest run` → all tests in `Panel.validation.test.js` pass (name-dedup, numeric bounds, default-name lists, `getDefaultDiscountRange`)

### Smoke
No agent-executable smoke checks — this feature's Agent Verification Plan (tech-spec) explicitly has no MCP/curl-checkable surface. `npx vitest run` above is the only automated check this task runs.

### User
Ask the user to confirm the manual checklist in user-spec "How to Verify → User verifies" was walked through on poshivon.ru/panel (or local dev build), covering:
- Инкремент 1: mode order swapped, labels "Продвинутый"/"Быстрый", "Скидки за количество" label.
- Инкремент 2: add one row to each of the 3 blocks (Изделия, Усложнения, Скидки за количество), save, reload — all 3 persist and price correctly in both calculator modes.
- No "Удалить" on the 4 default Изделия / 8 default Усложнения; a working "Удалить" on admin-added rows.
- Delete an added row, save, reload — it stays gone.
- On Скидки за количество, "Удалить" is disabled on the sole remaining tier.
- Duplicate name (including case/whitespace variants) is rejected with "Такое название уже есть".
- `0` in Мин. цена/шт is rejected on the Изделия add-form.
- A discount tier added with the suggested default range saves without error.

Do not execute these in the browser yourself — report the user's confirmation (or lack of it) verbatim, and treat an unconfirmed checklist as a QA fail.
